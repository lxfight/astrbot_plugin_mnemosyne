# 性能与调优

Mnemosyne 的检索延迟主要来自 Embedding、向量数据库搜索、后处理和提示词注入。管理面板会展示这些阶段最近的 P50/P95/P99，默认保留当前进程内最近 1000 个样本，重启后清零。

## 先看分阶段指标

打开管理面板的性能指标，优先判断延迟出现在哪一段：

- **Embedding**：调用 AstrBot Embedding Provider 的耗时。持续偏高时先检查 Provider 网络和限流。
- **向量搜索**：后端执行 ANN 搜索的耗时。持续偏高时检查索引类型、集合加载状态和后端资源。
- **后处理**：参与者过滤、关键词重排和轻量图谱扩展的耗时。
- **记忆注入**：格式化并拼接到提示词的耗时，通常应远低于 Embedding 和向量搜索。
- **数据库操作**：记忆 insert/flush 的耗时。flush 成本通常明显高于 insert。
- **记忆查询**：一次完整 RAG 检索的总耗时。

超过以下阈值时会输出 warning：Embedding 500 ms、向量搜索 300 ms、后处理 100 ms、注入 50 ms、数据库操作 500 ms、完整检索 1000 ms。

## 检索路径与候选数

仅在查询包含可重排关键词或启用了参与者过滤时，检索才会扩大候选集：

```text
candidate_limit = min(top_k * 4, 60)
```

没有关键词且未启用参与者过滤时，`candidate_limit` 直接等于 `top_k`，避免无意义地放大向量搜索返回量和后处理开销。向量库返回候选后，再执行参与者过滤、关键词重排和可选的轻量图谱扩展，最后截取 `top_k` 条注入。降低 `top_k` 会同时减少向量搜索返回量、后处理 CPU 和最终提示词长度，是最直接的调优项。

## 可调参数

| 参数 | 影响 | 建议 |
| --- | --- | --- |
| `top_k` | 候选数、后处理量和注入长度 | 先用 3-5；延迟敏感场景不要盲目调大 |
| `memory_injection_interval` | 检索触发频率 | 高频对话可设为 2-5，减少重复检索 |
| `use_lightweight_memory_graph` | one-hop 扩展与重排成本 | 不需要关系扩展时关闭 |
| `use_participant_filtering` | 群聊参与者过滤 | 仅在群聊串线明显时开启 |
| `use_session_filtering` | 检索范围 | 关闭会扩大搜索范围，通常增加延迟 |

## 向量数据库

- 插件会在启动时为 Milvus 的 `session_id`、`personality_id`、`create_time` 自动补齐 `INVERTED` 标量索引，并为 Qdrant 创建对应的 `keyword`/`integer` payload index。
- Milvus `AUTOINDEX` 不需要 `nprobe`，插件默认不会再注入该参数。
- `IVF_FLAT`、`IVF_SQ8`、`IVF_PQ` 默认使用 `nprobe=10`。
- `HNSW` 默认使用 `ef=64`。
- `DISKANN` 默认使用 `search_list=16`。

如需自定义，可显式配置 `index_params` 和 `search_params`；`search_params.metric_type` 必须与索引的度量类型一致。

## 管理面板

统计、会话列表和资源统计使用 10 秒短期缓存，避免 dashboard 刷新时重复查询。删除或更新记忆后会立即失效相关缓存。

统计和会话列表按每批 2000 条流式聚合，不再截断到 10000 条；Chroma、Qdrant 和 Milvus 的总数优先使用后端原生计数，避免为了计数拉取整张表。

Qdrant 的管理端全量扫描使用原生 scroll 游标逐页推进，不再通过递增整数 offset 重复读取前缀；其他后端继续使用原生 offset 分页。

记忆搜索在无关键词时使用原生计数确定总数，再分页扫描并用小顶堆保留 `offset + limit` 窗口，不会把全量记录加载到内存。关键词搜索仍需扫描筛选范围内的记录，但已改为分批读取。

删除会话前的计数和资源面板的记录总数同样优先使用原生计数；不支持原生计数的自定义后端会回退到受控查询。

记忆导入和 Milvus 维度迁移会按每批 16 条调用 Embedding Provider 的批量接口，并在 Provider 不支持批量接口时回退到单条请求。

会话消息计数使用单条 SQLite 原子 upsert 完成创建或递增，连接复用路径不再执行额外的健康检查查询。

批量删除会按 200 条分块合并 ID 表达式，并在全部删除请求完成后只执行一次 flush。

导出仍保留 10000 条上限，这是安全边界而不是分页大小。数据量较大时，优先通过会话或日期筛选，避免频繁全量导出。

## 注意事项

向量搜索有 5 秒默认超时，但 Python 线程无法被 `asyncio.wait_for` 强制终止。如果面板持续出现搜索超时，应先检查向量数据库负载和网络，而不是继续提高超时或 `top_k`。
